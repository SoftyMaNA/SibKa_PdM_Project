# Лабораторная работа 7 – Прототип SibKa PdM

Реализован локальный веб-прототип на Python и Flask с существующей базой MySQL/MariaDB `sibka_pdm_v2` из лабораторной 4. Интерфейс продолжает макеты Figma из лабораторной 6.

## Возможности

- Обзор парка с количеством объектов, предупреждений и критических состояний.
- Поиск техники и просмотр её паспорта, узлов и последних показаний.
- Выбор техники и узла, графики последних 24 записей каждого датчика.
- Диагностика по индивидуальным порогам из `sensors`: значение на критической границе уже считается критическим.
- Отсутствующие и недостоверные показания имеют отдельное состояние «Нет данных».
- Создание заявки на узел с достоверным отклонением, её сохранение и диагностическое основание.
- Просмотр заявки, истории, списка, поиск и фильтр по состоянию.

Состояние рассчитывается по последним сохранённым данным. Старые записи не объявляются текущим потоком: даты явно показаны в UTC. ML-модель, интеграция с 1С, авторизация и обработка согласования не входят в объём этой версии. В справочнике выбирается автор заявки, это не вход пользователя в систему.

## Запуск на Mac

1. Скачайте ветку `feature/lab7-prototype` и распакуйте архив.
2. Запустите MySQL в менеджере XAMPP.
3. Убедитесь, что в phpMyAdmin доступна база `sibka_pdm_v2`. Если она уже импортирована в лабораторной 4, повторный импорт не нужен.
4. Откройте папку проекта в VS Code. В терминале выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp config.example.json config.local.json
python run_web.py
```

Требуется Python 3.11 или новее. Для XAMPP обычно достаточно значений из `config.example.json`; измените порт, имя пользователя и пароль в `config.local.json`, если у вас другие настройки. Этот файл исключён из Git.

Откройте **http://127.0.0.1:5001**. Сервер слушает только этот компьютер. Для остановки нажмите Ctrl+C в терминале.

Вместо ручных команд можно выполнить `bash Start_Mac.command` из папки проекта. Скрипт создаёт окружение и устанавливает зависимости. Он не импортирует SQL и не меняет данные базы при запуске.

## Проверка основного сценария

1. На обзоре откройте технику с критическим состоянием.
2. Перейдите в диагностику и выберите узел с отклонением.
3. Нажмите «Создать заявку».
4. Укажите автора, название, описание, приоритет и срок UTC в будущем.
5. Сохраните форму. Откроется карточка с номером заявки и записью истории.
6. Вернитесь к списку. Найдите заявку по её номеру.
7. Перезапустите приложение: запись останется в БД.
8. Для независимой проверки выполните `database/v2/Lab7_connection_checks.sql` в phpMyAdmin.

Заявка и основание записываются одной транзакцией; при ошибке выполняется rollback. История создаётся триггером лабораторной 4. Все SQL-параметры передаются отдельно от текста запроса. Отправка формы защищена сессионным CSRF-токеном.

## Автоматические тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests/ -q
```

Две основные функции тестирования лабораторной 7 находятся в `tests/test_web.py`: границы порогов и различение нормы / отсутствующих данных. Они параметризованы для нескольких входных наборов. Ранее разработанные тесты диагностики и телеметрии сохранены.

`tests/test_database_flow.py` проверяет HTTP-страницы, валидацию, CSRF, сохранение заявки, привязку диагностики и историю триггера. Для него требуется отдельная база `sibka_pdm_ci`; рабочая база пользователя не используется. Скрипт `scripts/init_ci_db.py` создаёт только эту новую базу и отказывается работать с другим именем.

GitHub Actions запускается при каждом push, pull request в main/develop и вручную. Два задания выполняют модульные тесты и проверки на MariaDB 10.11. XML-результаты сохраняются как артефакты Actions.
