# Проверка модуля телеметрии и диагностики

## Объект и границы

Проверяются реально исполняемые функции `collect_data`, `validate_data`,
`assess_condition`, `start_system`, командный интерфейс и коды возврата ОС.
Внешние датчики, БД, ML и 1С не подменяются фиктивно успешными проверками:
они не реализованы в текущем репозитории.

## Сценарии

| Группа | Вход или действие | Ожидаемый результат |
| --- | --- | --- |
| Сбор | Вызов без аргументов | Температура 85, вибрация 1.2, давление 10 |
| Внешние данные | Другие корректные показания и нули | Переданные значения сохранены |
| Независимость | Изменение результата после сбора | Вход и последующие результаты не изменены |
| Структура | Пропущенное или лишнее поле, пустой пакет | TelemetryError, без нормального статуса |
| Типы | Строки, bool, null, массивы и объекты в измерениях | TelemetryError с именем параметра |
| Числа | NaN, ±∞, переполнение числа | TelemetryError |
| Знак | Отрицательное давление или вибрация | TelemetryError |
| Температура | Отрицательные градусы Цельсия | Значение допустимо |
| Границы | Ниже warning, ровно warning, ниже critical, ровно и выше critical | normal, warning, warning, critical, critical |
| Несколько отклонений | Температура 95, вибрация 8, давление 17 | critical; три причины сохранены |
| Восстановление | Пакет с риском, затем нормальный | Второй результат без старых предупреждений |
| Профиль | Альтернативные корректные пороги | Использован переданный профиль |
| Ошибка профиля | Отрицательные, равные, обратные, бесконечные пороги | ValueError |
| CLI | JSON-файл с критическим показанием | JSON со статусом critical, код 0 |
| CLI ошибки | Повреждённый JSON, null, неверная телеметрия | Код 2, stderr, пустой stdout |
| Файловые ошибки | Несуществующий файл, неверный UTF-8 | Обработанная ошибка, код 2 |
| Процесс ОС | Запуск main.py и telemetry.py | Успешное завершение и проверенный вывод |
| Импорт | Импорт модулей отдельным процессом | Нет вывода и автоматического запуска |

Ожидания граничных тестов заданы независимо от реализации сравнения.
Тесты не ограничиваются проверкой отсутствия исключений: сравниваются
статусы, значения, список причин, канал вывода и код завершения.

## Условия прохождения CI

Все проверки должны пройти на каждой версии Python. Общая полнота покрытия
строк и ветвей должна быть не менее 90 %. Ошибка теста или недостаточное
покрытие делают job неуспешным. Отчёты сохраняются даже при ошибке тестов.
Результат локального запуска не равнозначен результату запуска GitHub Actions.
